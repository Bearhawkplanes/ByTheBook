# Build Checklist: notes for Claude

Offline Electron desktop app for shop build checklists: sections > cards > steps, each with specs, images and links into a PDF manual, plus check-offs, initials, sign-offs, PIN-protected roles and an activity log. Used in a real shop by a foreman and employees. `README.md` is the user-facing manual; keep it in sync with behaviour changes.

## Working on this repo
- The app is for any in-depth mechanical work, **not aircraft-specific** (owner's rule): keep every label, example, demo item, export and doc generic (no aircraft, wing, airframe… wording). Mechanics words (technician, inspector, torque, spec) appear only when the checklist's `S.mech` switch is on (Settings > This checklist, off by default; demo on); otherwise use general words. The page reference is "Ref. page".
- The owner (GitHub: Bearhawkplanes) is not a programmer. Explain changes in plain language, give them something concrete to try, and keep answers short.
- Workflow: commit to `main` and push after each finished change (the owner pulls it on their work and home computers). One logical change per commit, with a clear message. Update `README.md` in the same commit when behaviour changes.
- No build step. The only runtime dependency is `ffmpeg-static` (approved by the owner for video clips; unpacked from the asar via `asarUnpack`). Do not add frameworks or other npm packages without asking. `lib/` holds vendored pdf.js 3.11.174 (Apache 2.0) and `lib/fonts/` (six OFL sans fonts for text on images, subset to Latin + shop symbols as WOFF2, licenses in `lib/fonts/LICENSES.txt`); leave them alone.
- `index.html` is written in a dense style: compact one-line functions, short global names (`S`, `PR`, `CUR`), few comments that explain *why*. Match it; do not reformat or "prettify" existing code.
- Test: `node tests/main-test.js` runs the real `main.js` and `storage.js` against a fake Electron in a temp folder (PIN limits, E-4419, stamps). `node tests/page-test.js` loads the real `index.html` in headless Chromium with an in-memory stub for `window.fsapi` (Playwright and Chromium are preinstalled in Claude cloud sessions). Add a case there for new behaviour. It cannot test `main.js`/Electron itself; say so when reporting, and ask the owner to try `npm start`.

## Files
- `main.js`: Electron main process. Picks the `Data/` and `Saves/` folders (next to the exe, fallback Documents/Build Checklist), PBKDF2 PIN hashing, recovery codes, the signed profile and marker, and the `integrity()` check. Every page request goes through one IPC channel `fs` with a whitelist of `handlers`.
- `preload.js`: exposes those handlers to the page as `window.fsapi` (also the close-time `flush` handshake and `open-file`).
- `bcl.js`: the `.bcl` file format (pure Node): `'BCLC1\n'` header, raw media written once, then per save the checklist JSON + index JSON + 40-byte trailer appended (`save`); readers use the last complete trailer (crash recovery by scanning back); `compact` rewrites with only what is in use (automatic when dead space > max(64 MB, half of what is used)); `convert` turns an old plain-JSON file into this format; `readMedia`, `info`.
- `storage.js`: the save folder on top of bcl.js: per-file queue, one `.bak` per file in `Saves/Backups/` (every 5 min, 30 min over 100 MB), old files converted on first read (original kept as the backup), `media(n,key)`, `info`, `tidy` (compact when > 8 MB dead; the page calls it when switching checklists), `exportTo` (Save dialog), import / restore copy new-format files as they are.
- `index.html`: the entire UI and app logic in one inline `<script>`.
- `print.html`: the printable-checklist layout (see Export window).
- `splash.html`: the loading window. main.js `createWindow` shows it at once and keeps the main window hidden (`show:false`) until the page sends `ready` (`FS.ready()` after `openHome`, also on a start-up error; fallback 30 s); the page reports steps with `BOOT(text, fraction)` > `FS.loading` > `step()` in splash.html. `customSplash()` passes `Data/loading.<gif|png|apng|webp|svg|webm|mp4>` as `?c=` (`&v=1` for video). No picture during the portable exe's unpacking: electron-builder's `portable.splashImage` uses NSIS BgImage, untested on Windows (may cover the whole screen); `splash.html?still` gives a still frame if it is tried. Tests that drive the built app must pick the window whose URL has `index.html`, not `firstWindow()`.
- `tests/main-test.js`, `tests/page-test.js`: see above. `tests/electron-test.js` drives the real built app (needs `npx electron-builder --linux dir --publish never`, then `xvfb-run -a node tests/electron-test.js`): MP4 playback, ffmpeg clips and thumbnails. Run it after video changes.

## Data model (`.bcl` = JSON)
- Open checklist in memory: `S` = `{name, manual, pdfs[], sections[{title, sign, cards[{...item, steps[item]}]}], locked, log[], seg, segs{}, ids{}, stamp}`.
- Item fields (`mk()`): `text qty size spec desc page pdf media[] ver src` (content) and `done init doneAt sig sigDraft hist[]` (progress).
- `pack()` serialises `S`; media fields (`files{id}.data`, `pdfs[].data`, `videos[].data`) hold `'bcl-media:<key>'` for media already in the file (keys `m:`/`p:`/`v:` + id) or a data: URL for new ones, listed in `pack.fresh`; after a save that returns `{container:true}`, `flushNow` turns those records into references (`r.ref`, data dropped). `unpack()` turns references into `{ref}` records; `mBlob(r)` / `pdfBuf(r)` load them from the file (`FS.media`) when shown. Writes to another checklist (Save as, a new job, exports) pass `from` = the current file so main copies its media. Images live in `MEDIA`, PDFs in `PDFS`, copied-in videos in `VIDS` while open.
- Videos: `S.videos[{id, name, size, link}]`; `link` = `{path, rel, size, mtime}` (rel = relative to the save folder when inside it, so a USB drive works under any drive letter), or no link = copied in (data in `VIDS`, packed as `videos[].data`, max 300 MB). Item media for video: `{kind:'file', type:'video', id, thumb, clip:{start,end,q,sound}}` (installed clip, data in `MEDIA`/`files`) or `{kind:'vref', vid, start, end, thumb}` (plays part of a library video, looped). Assign flow: method (install / call) > `pickStep()` (step picker: hover highlight, click = persistent `.on` + green `.pkgo` button beside the row, click elsewhere clears; search, section tabs scroll to `.pka` markers, ↑/↓/Enter/Esc; starts on `PKLAST` or `SEL`) > `installWin` for installs. Videos show only `thumb` until clicked (`vidPlay`); `VEL` keeps loaded item videos, `vidMount()` (end of `renderR`) re-attaches them and releases other items' after 60 s. Big data URLs are decoded with `fetch()`, not `atob`. main.js: `videoPick/Info/Read/Temp/Thumb`, `clipMake` (ffmpeg, three qualities + optional sound, exact sizes, temp files under os.tmpdir), `clipRead/Done/Cancel`. Linked-file thumbnails come from ffmpeg (the page cannot read pixels of file:// videos).
- Drawings: image media can carry `draw={w,h,s:[{c,w,p:[x,y,...]}]}` in the image's own pixels (strokes only, never a second image). `mediaTools()` adds the pencil (`.ed`) and the eye (`dvis`, session-only `DHIDE`); `hydrate()` shows `shownUrl()` = a drawn-over copy cached in `DRC`. Editor: `drawOpen()` (`#dw`), undo/redo as stroke-list snapshots; pen colour/size remembered in `AS.dcol/dsz`. Text: `m.text=[{x,y,t,f,s,c,b}]` (image pixels; drawn by `paintText`, line height 1.2 like the HTML boxes; fonts are the bundled `TFONTS`, loaded with `txFonts()` before any canvas drawing; unknown names fall back to Inter via `tfOk`). Text mode is inline on the Images tab (`TX={mid,tool,sel}`; `txStart/txEnd/txMount/txPick/txSet`); `imgPane` renders `#txl` boxes (contenteditable plaintext-only) over the image; `select()` and leaving the image end it (`txEnd` drops empty boxes). Separate from the drawing editor by the owner's request. Videos chosen on the Images tab go to the player via `vidFromItem()` (needs `FS.pathOf` = Electron `webUtils.getPathForFile` to link).
- Picture descriptions: `m.cap` on item media (content). `imgPane` renders `.mcap` (Fit: under the picture; Stack: `.att` inside the tile) bound via `data-cap` in the `R` input handler (blocked by `isLocked()`, read-only then), Grid: `.gcap` with the first 10 words.
- Work photos: `item.wp=[{id,tid,name,by,uid,at}]` (progress, cleared by `blankCopy`; `wpL` reads, `wpOf` creates). `id` = the photo, `tid` = a 480 px JPEG preview, both in `MEDIA` and packed like other files. Tab `#p-wp` (`wpPane`, list `WPP`), page `#wg` (`wgRender`, by section, caption = main item, list `WPG`), full screen `#wf` (`wfShow`, ←/→/Esc, capture-phase keydown). `wpAdd` (needs no edit unlock; blocked by `errNow()` and by `wpLocked` = the main item has a `sig`), who from `askPin` when sign/names PINs are on, else `AS.wpby`. `wpDel` asks a Boss PIN in worker mode or with the sign PIN. Photos only (owner's decision: videos would make checklists huge; maybe later via a host computer).
- Autosave: `save()` debounces 3 s, `flush()` writes; also every minute and when the window closes.

## Profile, PINs and tamper detection (the sensitive part)
- `PR` = main profile `{pid, user, salt, hash, rv, req{names, sign, edit}, people[]}`, stored signed (HMAC with `BUILD_KEY` in main.js) in `Data/profile.json`; a signed marker `{pid, rv}` sits in `Saves/.profile-marker.json`. PINs exist only as hashes.
- Every saved checklist is stamped with `S.stamp = {pid, rv}` (in `pack()`).
- Error codes:
  - **E-4417 / E-4418** (`TAMPER`): the profile or marker is missing, edited or mismatched. Comes from `integrity()` in main.js. **Whole app view-only.** Fix: recovery code on the Profile page.
  - **E-4419** (`TAMPER`): 100 wrong PINs in a row. **Whole app view-only** until the recovery code is entered.
  - **E-4420** (`CLT`): the open checklist's stamp is not this profile's ID (another computer, a reset profile, or no profile yet). **That checklist only.** Fix: "adopt?" on the flagged row in Saved checklists (main or Boss PIN), or Profile > "Adopt this checklist". Logged either way. `storage.list()` reports each file's stamp (`pid`), cached by modification time.
  - Worker mode `S.worker` (Settings > This checklist, needs `PR.hash`): `isLocked()` like a master file, no delete (`noDel`), `wkGate()`: the menu opens with only `WKFREE` (save, export, wunlock) enabled until "Unlock menu (Boss PIN)…" (`data-m=wunlock`, `menuOpen(true)` for that opening); the cog asks `askPin({boss:true})` (`WKW` = who opened Settings, used in the log); Ctrl+N, Ctrl+Shift+S and `importPath` (Open with) are blocked. Off under `TAMPER` or without a profile (owner's rule: exports must stay possible). `pack()` puts `locked` and `worker` right after `stamp`, and `storage.list()` reads them from the head.
  - `errNow()` = `TAMPER || CLT` blocks checking, sign-offs and unlocking edits; viewing always works.
- PIN switches (`PR.req`): names, sign, edit, log (also whitelisted in `cleanProfile` in main.js). `boss:true` prompts accept the main profile or a Boss; only the Profile page and the recovery code are main-profile-only (owner's rule). `logOk()` gates every way into the activity log.
- PIN lengths: main PIN 5-8 digits (`MAINPIN`), everyone else exactly 4 (`EMPPIN`); entry boxes take 4-8 (`ANYPIN`, maxlength 8) and must not reveal the length (owner's request). An older 4-digit main PIN forces a change on the next Profile unlock (`NEWPIN`).
- Wrong-PIN limits live in main.js (`pinTry`), stored in the signed profile (`fails`, `until`) so a restart or the page cannot reset them; any correct PIN resets them, and so does the right recovery code (`recCheck`). 5 in a row: "Forgot PIN?" hint; every 15th: 20-minute wait; 100: E-4419. Every PIN a person types must go through `pinTry` (`whoIs`, Profile unlock); `matchPin` is only for checking whether a new PIN is taken. "Forgot PIN?" on the Profile page takes the recovery code without an error: it unlocks the page and clears waits; a new main PIN is optional when the profile file is intact (`canKeepPin`). Employee PINs are reset with "Set PIN". Developer tools are off in packaged builds (`devTools: !app.isPackaged`).
- Owner's rules (decided, do not undo):
  - Lock the whole app **only** when the profile settings themselves were tampered with. A copied checklist locks only itself.
  - The shop must never lose its files to a bad employee: even under E-4417/E-4418, checklists must still open and **Menu > Export… > Fresh copy** must still work.
  - Fresh copy export (`exportDlg` (the Export window, `#xp`) > `xpExport` > `blankCopy`) keeps all content, images and PDFs, and clears progress, stamp and `ids`. "Include the activity log" keeps the old log read-only under an "Exported as a fresh copy" segment, so the checks can be re-entered by hand in a new install.
- Security is deliberately "deters casual tampering". The README says what it does not stop; keep that honest when changing things.

## Updates (main.js `checkUpdate/downloadUpdate/installUpdate`, page `updRefresh/updBar`)
- `UPDATE_URL` = GitHub releases/latest (override `BCL_UPDATE_URL` for tests). State in `Data/config.json` `upd` {auto (off by default), last, skip, snooze, found}. Automatic checks at most ~once a day (`updCheck(false)`); the page calls it at start and every 3 h.
- Build kinds (`kind()`): portable exe (`PORTABLE_EXECUTABLE_FILE`, asset `BuildChecklist.exe`), Windows installer (asset `BuildChecklist-Setup.exe`, just run it), AppImage (`APPIMAGE`, asset `BuildChecklist.AppImage`). Download goes next to the program as `.update-<name>`, size + `digest` (sha256) checked; install keeps `<name> (previous)` and a helper (PowerShell / sh) waits for this process to exit, swaps and relaunches with the same `--flags`.
- Version stamps: `.bcl` gets `app` (version that saved it) in `pack()`; a newer file opens with `RO` set (E-4421 in `errNow`, view-only, `save`/`flushNow` never write). The profile gets `app` in `cleanProfile`; `profileSave` refuses to overwrite a newer one.
- Tests: `tests/main-test.js` (fake GitHub server), `tests/page-test.js` (bar, Settings, read-only), `tests/update-test.js` (real self-update of two builds; Linux AppImage here, Windows via `.github/workflows/update-test.yml`, run from the Actions tab). Test hooks in main.js: `BCL_VERSION_MARK`, `BCL_UPDATE_AUTO`.

## Size and speed (measured with `tests/stress-gen.js` + `tests/stress-test.js` on the built app)
- The bcl.js format keeps media out of the checklist JSON, so there is no text-size ceiling and a tick appends only the checklist. Limit per checklist: `CAP` = 2 GB (under FAT32's 4 GB with room for compaction); `roomFor()` refuses new media past it; Settings > This checklist shows the storage bar (`stFill`, `usage()` = saved size from `FS.info` + unsaved media).
- The list is drawn per section (`renderL`: `.secw[data-sw]` wrappers; only sections within ~800 px of the view, plus those of `SEL`/`ER`/`ES`, get `secHTML`; the rest are placeholders of their last measured height `SECH` or `secEst`, filled by an IntersectionObserver `LIO` or `mountSec`/`mountNear`). A tick, sign-off or expand calls `renderCard(si,ci)` (one `.card[data-ck]` + `renderCounts`), not `renderL`. Search keeps hits as data (`LHITS`), Enter moves without redrawing. Never query `#L .row` expecting every row: mount the section first. `hydrate` lets go of file-backed images after 60 others (`UORD`/`urlTrim`). `pack()` deep-copies `S` only when a `strip` is given. storage: backups run beside saves (`bgBackup`, copy up to the last complete save; compaction waits for them via `beforeCompact`); `ready` skips the queue for files already in the new format; `bcl.save` stores the text as is when it has no new media (no parse/stringify). Weak-laptop probe: `taskset -c 0,1` + CDP `Emulation.setCPUThrottlingRate` 4 (scratch script, see git history of this note).
- Keyboard (one document keydown handler after the `ACTS` list): `SIDE` 'list' / 'right' (`sideSet`, Tab / Shift+Tab, mousedown on `#L`/`#R`; marker `.kside` on `.stabs` / `.tabs`); list: `listStep(d, 'row'|'card'|'sec')` over `flat()` (cards + open steps), `goRow`; right: `tabStep` over `TABS` (no wrap); ←/→ `contentStep` (Fit pictures, PDF pages; setTab > pdfShow returns to the row's page). Tab while typing in `#L`/`#R`/header = `boxStep` (next box, buttons skipped), Esc blurs. Shortcuts: `ACTS` ({id,t,def,run,any}), keys `AS.keys` (id > combo, '' = cleared; `keyOf`), combos by `comboOf` (letters/digits by `e.code`), Menu > Shortcuts… `keysDlg` (recording via `KREC`, capture keydown; `RESERVED` fixed keys; a taken key moves). Undo / redo: `umark(key)` snapshots `S.sections` + `selPath()` before content changes (one per typing box via `key`), `urestore`, `uclear` on check-offs / initials / sign-offs / work photos / Uncheck everything / opening a checklist (owner: evidence is never undone); deleted rows keep their media in memory for undo. Building keys: `addSection` (Ctrl+B, sets `SSEC`), `addItem` (Ctrl+N), `addStep` (Ctrl+M) start in rename mode; Delete/Backspace `delSel` / `delSection` ask unless `blankIt`. Owner's default keys: Save, Save as, Undo, Redo (Ctrl+Shift+Z, not Ctrl+Y, also in the drawing editor), Rename R, Ctrl+B / Ctrl+N / Ctrl+M; New checklist has none. `nt` actions (undo/redo) never fire while typing; other Ctrl/Alt actions blur the box first; shortcuts never fire in pop-ups (`popOpen`), and without Ctrl/Alt never while typing. Navigation only when `mainFree()`.
- Title line: `renderCounts()` shows Items (main items done) / Sections (all main items done = green, `secDone`) and the pie `#pie` (`--p` = % of main items done). Greyed-out menu items use class `.dis` + a reason in `title` (real `disabled` buttons show no tooltip); the menu click handler ignores `.dis`. The demo is loaded by `loadDemo()` (`#hDemo` on the main menu; no longer in the ☰ menu).
- Right-click on pictures: `contextmenu` > `imgTarget` (work photo tiles map to the full photo via `WPP`/`WPG`; link/data pictures use `src`) > `cmShow` menu `#cm` > `imgSave` (`FS.saveFile` with `dir` = `AS.imgDir`, remembered from the returned path; main uses `o.dir` for the Save dialog) / `imgCopy` (PNG to the clipboard).
- PDF Viewer page list `#pvpages` (right of `#pvmain`, width dragged on `#pvgrip`, `AS.pvw`): chapters = the PDF entry's own `P.ch=[{id,t,p}]` ("Chapter n: " + `tcase(t)`, sorted by page; right-click to rename/move/delete) or, without them, the PDF's top-level bookmarks; `bookmarks(doc)` resolves every level (named dests, GoTo actions), deeper ones (or all, with own chapters) become page names; `BMK[pdfId]` and `LABS[pdfId]` (page labels; filled by `indexAll`, `LABS[ACT]` also by `tocBuild`) plus the result counter `#pvnav` over single words: `pvSearch.h` = hits ({r: result row, j: n-th word on that page, -1 for non-word results}), `pvSearch.k` current hit, kept while `pvSearch.q` is unchanged; `pvHL()` (after each `draw()`) marks the words on the page shown in `#pvhl` over `#cv2` (positions from `getTextContent()` items joined with ' ' like the index, letter widths measured with `MC` in the item's font family), current = `HLCUR`; during a search `tocRender` fades non-matching pages (`.dim`), opens chapters with hits (`TOC.ss` = folds toggled during this search) and `AS.pvonly` hides the rest; `pvRes`/`pvStep`/`pvNav`; `openP` lets the last request win via `OPQ`/`openP.want` when clicks arrive while a PDF loads) let `pvSearch` find bookmarks, chapters and the PDF's own page numbers ("2", "p.2", "page ii"; owner's decision: the search box uses the PDF's numbers, the page box `#pvpg` the file's). `tests/make-workbook-pdf.js` writes a realistic test PDF (labels, named dests, nested bookmarks). Page rows always start "p.N" + label + `P.map` names; highlights `P.hl={page:key}` (`HLC` colours) colour only the list. Fold state `TOC.shut` (session). Options dropdown `#pvom` (`pvOpts`, button at the right end of the page-number bar in `.pvow`): add chapter (`chAsk`), highlight (`hlSet`), fold all, page numbering `pvNum()` = `AS.pvnum` both / book / file (`pnum()` in `tocRender`, also on chapter headers; old `AS.pvnolab` = file), hide the PDFs list (`pvSide`, `AS.pvshut`, ◀/▶ `#pvhide`). Chapter/highlight edits go through `pvEdit()` (blocked by `isLocked()`). `show()` calls `tocMark()`.
- `pack()` puts `app` and `stamp` first; `storage.list()` reads the stamp from the start of the checklist JSON (new files) or scans old files in 4 MB pieces. Search redraws 200 ms after typing stops. `shrinkImg()` shrinks photos on attach (AS.shrink, default on, 2560 px JPEG 86%; PNG screenshots stay PNG unless > 3 MB).

## Future plan: host computer (owner's idea, NOT started; first a stable, tested release)
Agreed with the owner, to build later, only when they ask:
- One always-on **host computer** stores the shop's checklists. Each project has **one laptop** that everyone on that project uses; another project uses another laptop.
- **Local first, mirrored to the host:** the laptop keeps working from its own copy (fast, works without Wi-Fi). After every save it sends the host what changed (bcl.js already appends each save, so usually only the new tail of the file). If the host cannot be reached, changes queue up and are sent later, with a small "not backed up to host since …" warning.
- **The host copy is independent evidence:** logs, work photos and saves are stored on both, identical, but the host never deletes because a laptop said so. A deleted checklist or removed photo on a laptop stays on the host with its earlier versions, so a crashed laptop, a failed drive or a worker deleting evidence never loses the record. The host can show/restore earlier versions.
- **"In use" lock held by the host:** opening a checklist marks it taken by that laptop; any other laptop gets view-only ("In use on <laptop>"). A Boss PIN can release a lock if a laptop dies.
- The host runs the same app in a "host mode" (no extra software, shop network only, no internet). Laptops are paired to it once with a code.
- Videos for Work Photos may come back then, stored only on the host (owner's decision: not inside laptop checklists).
- **Phones (owner wants this one day, after the host):** the host also serves the app as a web page on the shop Wi-Fi, opened in a phone browser (add to home screen; no app store, iPhone and Android). Reuse index.html's logic with a phone layout: pick a checklist, tick steps, PIN sign-in, and **Add work photo straight from the camera** (`<input type=file accept=image/* capture=environment>`), stored on the host and shown on the laptop. Probably no editing of the checklist content on phones. Same "in use" rules as laptops. This is why a rewrite in another language is not worth it (owner agreed): the web-based app is what makes the phone version cheap.
- Still to decide with the owner: how long the host keeps old versions, who can view/restore from it (main profile only or Bosses too), and a second backup drive for the host itself.

## Releases
- Windows downloads are built by `.github/workflows/release.yml` on GitHub Actions when a release is published, and attached to it. Never commit built `.exe` files or `dist/` to the repo.
- To release: bump `version` in `package.json` (and `package-lock.json`), commit and push; then the owner publishes a release on GitHub with tag `vX.Y.Z` (cloud sessions cannot push tags: HTTP 403). Ask the owner before preparing a release.
